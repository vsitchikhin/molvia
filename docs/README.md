# Где что лежит

Проект живёт в трёх местах, и это разделение намеренное.

| Что                               | Где                              | Почему там                                                                        |
| --------------------------------- | -------------------------------- | --------------------------------------------------------------------------------- |
| Правила разработки                | `CLAUDE.md` и `.claude/rules/`   | Меняются вместе с кодом и должны ревьюиться в том же коммите                      |
| Продуктовый план, дизайн, решения | Confluence, пространство **MOL** | Не следуют за кодом и обязаны пережить потерю диска: там версии и резервные копии |
| Задачи, эпики, спринты            | Jira, проект **MOL**             | Трекер                                                                            |

## С чего начать новой сессии

| Файл                 | О чём                                                                                                      |
| -------------------- | ---------------------------------------------------------------------------------------------------------- |
| `docs/onboarding.md` | Что за продукт, что уже сделано, откуда брать работу, какие решения не переоткрывать                       |
| `docs/tracker.md`    | Jira и Confluence: чего не умеет MCP, идентификаторы полей, ловушки                                        |
| `CLAUDE.md`          | Ядро правил: архитектура, границы слоёв, деньги, тесты, коммиты — и по строке на правило каждой области    |
| `docs/map/`          | Карта кода: файл на область, названный как её правила, — где что лежит, открывать до поиска по репозиторию |

## Правила по областям

`CLAUDE.md` грузится в каждую сессию целиком, поэтому в нём только то, что касается всего
проекта, и по строке на правило области, которое легко сломать. Разбор — что замерено, что
опровергнуто, какой ценой принято — лежит в `.claude/rules/<область>.md`. Claude Code грузит
такой файл, только когда работа читает файлы из его `paths:` (MOL-130).

| Файл                 | Область                                                                   |
| -------------------- | ------------------------------------------------------------------------- |
| `search.md`          | поиск по справочнику, транслит, словарь синонимов, запомненный выбор, сид |
| `advice.md`          | «Что брать», вердикты, журнал событий и ворота 0.2 и 0.3                  |
| `money-rates.md`     | официальный курс, свой курс из обменов, доходы, сторона печати курса      |
| `money-spendings.md` | траты, месяц, экран «Деньги» и его очередь                                |
| `money-accounts.md`  | счета, остатки, «списано», сверка                                         |
| `trips.md`           | «Покупки», ручная запись, очередь на устройстве, удаление, настройки      |
| `barcodes.md`        | сканер штрихкода, код, набранный руками, позиция по коду (MOL-99)         |
| `auth.md`            | сессии, запрос входа, cookie, экран входа, выход и «Устройства»           |

**Карта кода** (`docs/map/`, MOL-133) говорит «где», правила — «как нельзя». Файл карты на область
назван как её файл правил; `docs/map/README.md` — соглашения, список областей и каркас, не
принадлежащий ни одной. Карта не лежит в `.claude/rules/`: файл правил приходит в контекст только
после чтения файла области, то есть уже после поиска, — а карта нужна до него. Её сверяет
`bin/check-code-map.mjs` в `make lint`: файл без записи, запись без файла и файл в двух областях.

Новое правило области пишется в её файл, в ядро — только строка, если правило легко сломать.
Правило всего проекта — в `CLAUDE.md`. Новая область — новый файл со своими `paths:`, строка
в этой таблице и файл карты с тем же именем. Хроника задач — не правила, она в `docs/onboarding.md`.

## Что вне репозитория

`.scratch` — симлинк на `../_shared/molvia/scratch`, общий на все рабочие копии и вне
гита. Там лежит выгрузка от Claude Design: кликабельный прототип, 14 скриншотов в двух
схемах, исходные токены. Это замороженный артефакт поставки — его не правят, а читаемые
копии текстов из него есть в Confluence.

**Там же живут требования и планы задач** — `.scratch/tasks/requirements/MOL-<n>.md` и
`.scratch/tasks/plans/MOL-<n>.md`, пути зафиксированы в `CLAUDE.md`. Порядок жёсткий:
сначала требования, потом план, потом апрув владельца, и только затем код. В комментарий
к задаче план не пишется: его нельзя править вместе с работой, нельзя посмотреть диффом
и нельзя открыть, когда трекер лежит. Каталог общий на все копии, так что «план не виден
из другой копии» здесь не возникает. Карта каталога — `.scratch/README.md`.
